Project Vision (The Big Picture):
We are building a lightweight, highly modular, and LLM-agnostic chatbot gateway in Python.

Core Concept: A common LLM wrapper interface that allows seamless switching between different LLM providers (e.g., Gemini, OpenAI, or a Dummy-Provider). Providers will be cleanly separated in a providers/ directory.

State & Backups: The entire state (bot settings, API keys, and later the chat history) will live inside a single braindump.json file. This enables a 1-click "Download Backup" feature later.

Extensibility: Future plans include adding tool capabilities via MCP (Model Context Protocol).

Deployment: The final application will run in a super lightweight Docker container.

Frontend: Cleanly separated, dependency-free vanilla HTML/JS/CSS served by the backend.

Constraint: While this is the grand vision, we are starting extremely small. Please keep this architecture in mind for your design decisions, but do NOT implement the chat, LLM wrapper, Dockerfile, or MCP yet. Focus strictly on Step 1.

Context & Goal for Step 1:
Build the first milestone (MVP). For this first step, we do not need chat functionality and we do not need an actual LLM connection. The goal is solely to set up the project scaffolding (Backend & Frontend) and establish state management using a local JSON file (braindump.json).

Technology Stack:

Backend: Python 3.11+, FastAPI, Uvicorn, Pydantic (for data validation).

Frontend: Vanilla HTML, CSS, JavaScript (no frameworks like React or Vue, keep it extremely lightweight).

2. Data Model & State Management (app/config.py & data/braindump.json):

Create a Pydantic model for the app settings.

Fields & Validation Rules:

bot_name: String, maximum 15 characters. Default: "MyBot".

system_prompt: String, maximum 100 characters. Default: "You are a helpful assistant."

api_key: String (no length limit for now, can be empty). Default: "".

Logic: Write asynchronous functions to read and save this Pydantic model to data/braindump.json. If the file does not exist on startup, create it using the default values.

3. Backend API (app/main.py):

Initialize the FastAPI application.

Mount the static directory so HTML, CSS, and JS files can be served.

Create the following endpoints:

GET /: Serves static/index.html.

GET /api/settings: Returns the current content of braindump.json.

POST /api/settings: Accepts a JSON payload, validates it against the Pydantic model, and saves it to braindump.json. Returns a 200 status code on success, or a 422 status code (FastAPI default) if validation fails.

4. Frontend (static/index.html, style.css, main.js):

HTML: Create a simple, clean, and modern UI (a form) with three input fields for bot_name, system_prompt, and api_key, along with a "Save" button.

JS Logic: * On page load (window.onload): Make a fetch call to GET /api/settings and populate the input fields with the current values.

On Save click: Prevent the default form submission, gather the data from the inputs, and send it as a JSON payload via POST /api/settings.

Show visual feedback to the user (e.g., a small "Successfully saved" message, or an error message if the 15-character limit was exceeded).

CSS: Keep it minimalist. Use CSS variables for a clean, lightweight design without external dependencies (do not use Bootstrap/Tailwind).
